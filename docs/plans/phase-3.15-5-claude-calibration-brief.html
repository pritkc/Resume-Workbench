Cover letter input: restructure the entire prompt payload (~54% token reduction)

Three changes together bring the CL prompt from ~4,950 tokens to ~2,289 tokens.

1. Remove CANDIDATE PROFILE. It is a redundant subset of TAILORED RESUME. Gone.

2. Replace raw JD with a narrative slice of the JD extract. The job_keywords dict (from the first LLM call) is already passed to generate_cover_letter_and_outreach but only used for metadata today. Use it directly — slice to: role, company, responsibility_themes, calibration. Skip the ATS/keyword fields — those are resume-tailoring fields, not CL-writing fields. If job_keywords is unavailable, fall back to raw JD trimmed to 1,500 chars.

3. Strip TAILORED RESUME of all duplicates. Keep all experience entries (full career breadth matters). Per entry, keep: position, company, location, start_date, end_date, techStack, highlights. Remove: id, title, date, years, description. Same pattern for projects. From personalInfo: keep name, location, title/headline; remove contact details. Remove sectionMeta entirely.

P1 — Next Iteration

resume_generate_full cap of 15,000 is never needed — replace with adaptive formula

The RESPONSE CONTRACT already encodes the exact output grid before the call (bullet counts, project counts, skill value counts). From this test run: 34 tokens/cell empirical, 1.24× pretty-print multiplier. The formula below produces a cap that tracks actual resume size instead of a fixed worst-case ceiling.

cells = exp_bullets + proj_bullets + skill_values + scalar_cells
cap = max(6000, min(8000, ceil(cells × 34 × 1.25 × 1.40)))

This test run: 66 cells → cap = 6,000 (observed 2,809 → 2.14× headroom)
Very large resume (131 cells) → cap = 7,781 — still within 8,000 ceiling
Store computed cap + cell counts in trace metadata for ongoing calibration.

Inner LLM timeout is unreachable — disconnected from 240s outer wall clock

At max_tokens=15,000 the inner timeout formula gives ~659 seconds. The outer preview route aborts at 240 seconds. The inner timeout is dead code. Even after the cap drops to 8,000, per-call overrides are needed to make inner timeouts enforceable.

extract_jd_intel → 90s  |  resume_generate_full → 170s

Add optional timeout_seconds param to complete() and complete_json() in llm.py.
P1 — Next Iteration

Bold keywords: methodology labels leaking through on low-signal JDs

This test run produced SDLC, Software Testing, and Relational Databases as bold keywords — all prohibited by the schema rules ("prefer tools, languages, platforms; avoid generic labels and umbrella terms"). The failure mode is specific: when the JD names no high-signal technical tools, the model defaults to methodology labels.

Add one line to output_file_schema_rules/resume_diff_output.txt:

"Also exclude: methodology labels (SDLC, Agile, CI/CD pipeline, test automation), generic infrastructure categories (Relational Databases, Cloud Storage, Distributed Systems), and competency phrases (Test Case Design, Project Management). When the JD names no high-signal tools, draw bold_keywords only from tools, languages, and platforms in the resume evidence."
P2 — After Telemetry

Model ignores minification instruction — measure before tuning

Both JSON responses came back pretty-printed inside triple-backtick fences. The prompt explicitly requests minified, fence-free JSON. Parser recovers, but this wastes ~147 tokens (extract) and ~544 tokens (tailor) per call — ~400K output tokens/month at 25 runs/day. Do not change the prompt wording without first measuring fence frequency across models.

Add to every JSON call trace in llm.py:
response_had_fence: bool, raw_response_chars: int,
minified_chars: int, formatting_overhead_chars: int
