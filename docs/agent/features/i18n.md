# Internationalization (i18n)

> **UI strings, content language for the LLM, and how this repo actually behaves today.**

## Runtime truth (read this first)

- **`apps/frontend/i18n/config.ts`** exports **`locales = ['en']` only** — the app router and `getMessages()` path are **English-only** at runtime.
- **`apps/frontend/messages/`** contains JSON for **en, es, ja, zh, pt-BR** (and more may appear). Those files are **prepared for future locales**; they are **not** all registered in `lib/i18n/messages.ts` until product enables them.
- **`apps/backend/app/routers/config.py`** defines **`SUPPORTED_LANGUAGES = ["en"]`** for persisted UI/content language settings. Expanding locales requires updating **frontend `i18n/config.ts`**, **`lib/i18n/messages.ts`**, **backend `SUPPORTED_LANGUAGES`**, and prompt language maps (see `app/prompts/_constants.py` `LANGUAGE_NAMES`).

## Two language settings (Settings page)

1. **UI language** — interface text (when additional locales are wired into `i18n/config.ts` and `getMessages`).
2. **Content language** — passed to LLM prompts for generated resume/cover-letter text (`LanguageProvider` + backend config).

## Key files

| File | Purpose |
|------|---------|
| `apps/frontend/messages/*.json` | UI translation source files |
| `apps/frontend/lib/i18n/messages.ts` | Maps active locale → message object (today: `en` only) |
| `apps/frontend/lib/i18n/translations.ts` | `useTranslations` hook |
| `apps/frontend/lib/context/language-context.tsx` | UI + content language state |
| `apps/backend/app/prompts/_constants.py` | `LANGUAGE_NAMES` for prompt metadata |
| `apps/backend/app/prompts/*.py` | Prompt modules use `{output_language}` / language name helpers — **not** a single `templates.py` |

## Using translations

```typescript
import { useTranslations } from '@/lib/i18n';

const { t } = useTranslations();
<button>{t('common.save')}</button>
```

## Storage

| Key | Purpose |
|-----|---------|
| `resume_matcher_ui_language` | UI language (localStorage) |
| `resume_matcher_content_language` | Content language (localStorage + backend) |

## Adding a new language (checklist)

1. Add or complete `apps/frontend/messages/{code}.json`.
2. Add the locale to `apps/frontend/i18n/config.ts` and `apps/frontend/lib/i18n/messages.ts`.
3. Extend `SUPPORTED_LANGUAGES` in `apps/backend/app/routers/config.py`.
4. Extend `LANGUAGE_NAMES` in `apps/backend/app/prompts/_constants.py` if the LLM should name the language.

## Historical note

Older docs referred to `next-intl` and `templates.py`. The current stack uses the files above and split prompt modules under `app/prompts/`.
